# Spec Delta

## Purpose

iOS 以宿主为单位授予部分权限，而同一宿主内可以打开多个由不同作者编辑的项目。用户需要在调用发生时知道哪个项目正在使用哪项能力，并能分别限制和撤回访问。

## ADDED Requirements

### Requirement: 项目与系统分别授权

宿主 SHALL 在调用前逐项检查清单声明、该项目的用户授权、平台和硬件可用性、已签名的 entitlement 及适用的 iOS 权限，按需请求原生授权。项目修改自己的权限清单只会改变其申请范围。

#### Scenario: 第二个项目申请已授予宿主的相机权限

- **WHEN** 用户曾允许 A 使用相机，B 首次声明并请求相机
- **THEN** 宿主仍要求用户为 B 作出选择。拒绝 B 后，相机不会为 B 开启，A 的记录仍归 A。

#### Scenario: TSX 首屏连续申请未决定的项目权限

- **WHEN** 项目在首屏首次使用数据库和文件读取，用户依次选择允许数据库、拒绝文件读取
- **THEN** 两个系统提示依次关闭，原项目可以保存并重新读取其数据库。文件调用返回权限拒绝。重启后沿用该项目的两个决定，关闭尚未作答的项目会话不会写入授权决定。

#### Scenario: 签名缺少能力

- **WHEN** 项目声明并申请当前签名未具备的能力
- **THEN** 调用方收到指明签名条件的不可用结果，设置界面说明该条件，系统授权弹窗不会被当作补救手段。

### Requirement: 报告系统可观测的权限状态

权限管理器 SHALL 支持查询项目授权及系统公开的状态，区分可请求、已拒绝、受限、有限访问、不可用和系统不披露的状态。不能再次弹窗时，向用户提供适用的设置入口或操作说明。

#### Scenario: 用户改动系统权限

- **WHEN** 用户在系统设置撤回麦克风权限后返回项目
- **THEN** 下一次录音按当前权限返回拒绝结果，用户能查看重新授权方式。

#### Scenario: 系统对健康数据隐藏读取决定

- **WHEN** 项目查询系统未公开读授权结论的健康数据类型
- **THEN** SDK 表示该项结论不可查询，按系统返回的可见范围读取数据，空结果不会被推断成授权或拒绝。

### Requirement: 审计与撤销

宿主 SHALL 按项目记录能力、时间与访问结果，允许用户检查和撤回项目授权，并终止依赖该授权的持续订阅。记录中仅保留诊断所需信息。

#### Scenario: 撤销正在使用的定位权限

- **WHEN** 用户在宿主管理界面撤回当前项目的位置权限
- **THEN** 项目停止接收位置样本，使用记录显示撤回事件和后续拒绝结果，日志不保存精确坐标。
