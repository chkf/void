# Spec Delta

## Purpose

外部编辑器保存文件后，运行中的 React/TSX 和 Web 项目按修改范围应用新版本。更新过程需要保护当前可用页面、记录发布结果，并让用户在编译失败、启动异常或中途退出后能继续使用项目。SwiftUI 源码通过重新编译和安装 IPA 更新。

## ADDED Requirements

### Requirement: 按变更范围选择更新方式

运行时 SHALL 对样式和支持热替换的模块使用 HMR，对可重新载入的业务逻辑使用 Hot Reload，对入口、依赖、配置或不兼容边界使用 Full Reload，对执行环境失效使用 Runtime Restart。支持保留状态的边界须能报告状态是否恢复。

#### Scenario: 从样式改动到入口改动

- **WHEN** Agent 依次修改 CSS、支持模块重载的业务逻辑以及入口配置
- **THEN** CSS 在当前页面生效并保留输入状态，业务逻辑重新载入，入口改动触发完整重建和页面切换。诊断记录每次实际采用的方式。

#### Scenario: 执行环境终止

- **WHEN** 网页进程在增量更新过程中终止
- **THEN** 宿主重建执行环境，从最近可运行的版本打开项目，清理旧会话中的挂起请求和订阅。

### Requirement: 仅发布完整一致的版本

运行时 SHALL 在暂存区完成构建、校验输入版本与产物，并记录更新前快照。只有完整的候选版本可以激活，启动检查通过后才标记为可运行。

#### Scenario: 构建过程中再次保存文件

- **WHEN** 首次构建尚未完成时 Agent 又写入了新修订
- **THEN** 已过期候选版本被丢弃或重新构建，当前页面继续使用完整旧版本，最终仅激活与最新稳定输入匹配的产物。

### Requirement: 更新失败后继续运行

运行时 SHALL 在编译、发布或候选启动检查失败时保留或自动恢复上次可运行版本，保留 Agent 的源码修改和用户已提交的数据，并记录故障原因。

#### Scenario: 语法错误及启动崩溃

- **WHEN** 一次更新包含语法错误，或成功编译的候选在首次启动完成前崩溃
- **THEN** 用户仍可使用旧版本，Agent 能找到失败版本及原因并在原源码上修复，修复后的保存可再次触发更新。
