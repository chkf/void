# Spec Delta

## Purpose

项目可以发起需要时间的工作，并在 iOS 允许的条件下继续传输或处理。宿主在页面关闭、系统延后调度以及应用重新启动时都能确定任务归属，并将真实结果交还给原项目。

## ADDED Requirements

### Requirement: 选择系统允许的执行方式

宿主 SHALL 支持前台任务、长时间任务、后台刷新、后台处理、系统通知调度及获准的音频或定位后台模式。原生层负责调度，在可用系统上为符合条件的前台用户操作申请持续处理，报告排队、运行、完成、取消、过期和不可用状态。

#### Scenario: 系统延后或终止后台处理

- **WHEN** 项目请求后台处理，系统尚未安排执行，或在运行中发出到期通知
- **THEN** 前者保持待调度，后者保存可恢复的进度并结束本次处理。项目重开后能看到真实状态与原因。

#### Scenario: 不满足持续工作的条件

- **WHEN** 设备版本不支持持续处理，或应用不满足所需后台音频或定位条件
- **THEN** 宿主返回具体条件，并向项目提供可行的前台继续或系统调度方式。

### Requirement: 后台传输独立于网页会话

宿主 SHALL 通过系统后台传输设施进行文件上传与下载，持久化项目身份、任务标识、进度与终态，并在系统回调或恢复启动时完成交接。

#### Scenario: 上传期间切换项目

- **WHEN** A 启动后台文件上传，用户切到 B，随后系统向宿主交付结果
- **THEN** 结果持久化给 A，A 再次打开可查询到任务的实际终态，B 无法读取 A 的传输详情。
