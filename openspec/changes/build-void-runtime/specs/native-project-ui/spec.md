# Spec Delta

## Purpose

所有新建项目都使用 React/TSX 编写页面，组合宿主提供的原生控件并在手机上更新。

## ADDED Requirements

### Requirement: 创建 React/TSX 原生项目

宿主 SHALL 在用户输入名称并选定保存位置后直接创建 React/TSX 项目。创建页仅收集项目名称和保存位置。

#### Scenario: 创建项目并操作原生表单

- **WHEN** 用户创建项目并打开预览，在表单中输入名字并切换开关
- **THEN** React 状态随输入改变，SwiftUI 控件显示或隐藏相应的问候。冷启动后可以回到同一个项目。

### Requirement: 打开已有 SwiftUI 项目

宿主 SHALL 能重开已登记的 SwiftUI 工作区，并在预览时运行 IPA 中匹配的已编译视图。项目源文件有改动时，宿主须指出如何取得匹配的构建。

#### Scenario: 在文件夹中编辑 Swift 源码

- **WHEN** 用户添加、删除或修改项目中的 Swift 源文件
- **THEN** 宿主显示重新构建和安装说明，已打开的原生视图可继续使用。安装与目录源码匹配的 IPA 后打开更新过的项目。

### Requirement: 用 TSX 组成真实的 SwiftUI 页面

React/TSX 原生项目 SHALL 使用 `@runtime/ui` 的类型化组件，由宿主实例化 SwiftUI 文本、图片、按钮、堆叠布局、列表、分组表单、文本输入、开关、选择器、日期选择器、导航栈、工具栏和 sheet。此类项目可在同一个 IPA 中新增页面、调整结构、传递数据和响应事件。

#### Scenario: 仅修改源码增加原生设置页

- **WHEN** Agent 在项目 TSX 中新增一个含日期选择器和开关的表单，并从原生列表导航至该表单
- **THEN** 保存后已有 IPA 即可打开新页面。原生 UI 测试能找到 SwiftUI 表单中的系统控件并直接操作，控件变化进入项目逻辑。

#### Scenario: 请求宿主尚未提供的控件

- **WHEN** 项目声明了超出宿主控件版本范围的组件或属性
- **THEN** 构建或激活检查在替换当前可运行界面前给出组件名称、源码位置和所需版本，Agent 可改用支持的控件或更新宿主。

### Requirement: 原生交互与项目状态保持一致

宿主 SHALL 管理输入法组合文本、焦点、滚动、导航和弹层交互，将已生效的用户操作按会话交给 TS 逻辑。保留身份的控件在无关更新中保留原生交互状态。

#### Scenario: 中文输入期间刷新列表

- **WHEN** 用户正在搜索框输入尚未确认的拼音，项目更新搜索结果列表或热更新其他列表行
- **THEN** 候选词、光标和输入焦点得以保留，确认后的文本进入业务状态，用户无需重新输入。

#### Scenario: 手势返回或下拉关闭弹层

- **WHEN** 用户从详情页侧滑返回，或下拉关闭项目表单弹层
- **THEN** 系统完成相应交互，项目收到一次对应状态变化。取消侧滑时保留当前详情页，后续页面更新遵循实际导航栈。

### Requirement: 系统外观与辅助功能

宿主和项目原生组件 SHALL 使用 iOS 的动态字体、语义颜色、安全区域和 VoiceOver 角色，允许项目补充图标按钮的标签及控件可访问值。

#### Scenario: 调大文字并使用 VoiceOver

- **WHEN** 用户放大系统字体、切换深色外观并用 VoiceOver 操作一个项目表单
- **THEN** 标题、正文及控件跟随系统设置，表单仍可滚动，读屏能读出开关的名称、角色和值并改变它。

### Requirement: 同一项目可使用原生页面和 Web 页面

项目 SHALL 能为 HTML、Canvas、WebGL 或 Wasm 内容打开明确标识的 Web 页面，并与原生界面共享项目身份、权限规则和持久化数据。已有带 HTML 入口的 Web 项目可按原方式导入。

#### Scenario: 两类项目共用一个宿主

- **WHEN** 用户先打开带原生表单和 Web 图表的新项目，再导入已有 HTML/React 应用
- **THEN** 前者可在原生导航中进入图表并返回，后者从自己的 Web 入口运行，权限定向到各自项目。
