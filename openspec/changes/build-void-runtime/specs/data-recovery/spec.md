# Spec Delta

## Purpose

项目迭代时，用户需要保留已写入的数据，也需要在损坏、迁移中断或误操作之后恢复使用。存储与恢复按项目身份管理，允许用户分别处理源码、私有文件、缓存和备份。

## ADDED Requirements

### Requirement: 按项目持久化数据

宿主 SHALL 按稳定项目身份分别保存 SQLite 数据库、项目私有文件、缓存和备份，并将宿主管理数据和用户可编辑的源码分开。清缓存、重建、目录重命名及普通业务更新保留已提交数据。

#### Scenario: 两个项目使用同名表和文件

- **WHEN** 项目 A 和 B 写入同名表和文件，随后 A 清理缓存并升级源码
- **THEN** A 重开后可以读到自己的原值，B 的同名数据独立保存，两个项目无法读取对方的私有空间。

### Requirement: 备份、迁移与一致恢复

宿主 SHALL 自动备份用户数据，在更新前记录构建快照与数据模式版本，并对数据库迁移提供一致备份和中断恢复。只有数据模式兼容时才允许切换到相应的构建版本。

#### Scenario: 迁移过程中终止应用

- **WHEN** 新版本在迁移期间被终止并在稍后重新启动
- **THEN** 宿主恢复到完整的迁移前或迁移后状态，选择与之兼容的代码。诊断中可查询选用的备份、模式版本和恢复结果。

#### Scenario: 普通代码回滚后仍保留新数据

- **WHEN** 已运行的项目新增一条用户记录，随后因代码问题回滚到数据模式兼容的历史构建
- **THEN** 历史构建能读到该记录。若需要恢复旧数据备份，界面先说明影响并取得用户确认。

### Requirement: 按类别删除与恢复

宿主 SHALL 在移除项目时列出受影响的源码、用户数据、缓存和备份，让用户选择删除范围，对将丢失的内容给出具体确认，并提供从保留备份恢复的入口。

#### Scenario: 移除登记后恢复项目

- **WHEN** 用户只移除项目登记与缓存，随后重新选择同一目录
- **THEN** 源码、用户数据和备份仍在，宿主可恢复项目原有数据与已知可运行版本。
