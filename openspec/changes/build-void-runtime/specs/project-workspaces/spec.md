# Spec Delta

## Purpose

用户和外部编辑器可以在 Files 中操作同一份项目源码。独立的原生宿主管理界面维护项目身份、记住用户选择的目录，并在文件服务商延迟同步或收回授权时提供恢复入口。

## ADDED Requirements

### Requirement: 选择目录并恢复访问

宿主 SHALL 允许用户选择本地、iCloud 或支持目录访问的 File Provider 文件夹，导入外部项目时将完整项目文件夹复制到应用文稿并登记副本。在外部创建的项目与旧版外部登记按书签访问。

#### Scenario: 导入外部项目作为本地副本

- **WHEN** 用户选择一个外部项目或含多个项目的父目录
- **THEN** 宿主先复制并校验所选项目，再发布到应用文稿。之后从本地副本读取源码和共享数据。导入同名目录、遇到项目身份冲突或取消时，已有目录和登记得到保留。

#### Scenario: 再次启动已授权项目

- **WHEN** 上次使用的目录仍可访问，用户重新启动宿主
- **THEN** 宿主解析书签并打开原项目。脚本项目加载停用期间保存的源码，SwiftUI 项目核对源码与已安装的编译版本。

#### Scenario: 用户撤销目录授权

- **WHEN** 书签无法恢复有效访问
- **THEN** 宿主显示受影响的项目，保留其登记和数据。用户可返回项目列表，通过「导入文件夹」重新选取原目录。

#### Scenario: 原位升级后预览既有目录

- **WHEN** 用户原位更新宿主后从最近记录预览既有项目
- **THEN** 宿主在协调访问的原目录中独立读取清单及声明的入口，用逻辑相对路径收集源码，并核对原目录和项目身份。有效原目录继续使用原宿主 UUID、权限、构建与数据库。诊断区分缺失、未下载、读取失败、坏 JSON 和目录枚举遗漏。

#### Scenario: 系统文件夹选择结束

- **WHEN** 用户从列表导入文件夹或为新项目选择保存目录
- **THEN** 请求关联固定操作，创建表单关闭后才显示系统选择器。系统返回所选文件夹即开始处理，即使系统先关闭了选择器。选择和取消分别以对应的回调为准，同一请求只处理一次。等待协调时可以取消，超时调用系统协调器的取消方法。诊断按请求记录回调、授权、目录读取及结束状态。

### Requirement: 项目格式及管理

宿主 SHALL 支持创建、导入、发现、重命名、切换项目及从列表移除项目。「所有项目」按名称列出可见项目，保留启动时恢复的项目 ID，不采集打开时间。项目以稳定身份关联数据。

#### Scenario: 创建可供 Agent 编辑的项目

- **WHEN** 用户在此 iPhone 或在系统选择器指定的文件夹中创建项目
- **THEN** 宿主生成 React/TSX 项目，包含 `runtime.json`、`app/manifest.json`、`app/package.json`、`app/src/main.tsx`、`assets/`、`modules/`、`data/`、`logs/` 和 `README.md`。Agent 可在项目目录读取 `SDK_REFERENCE.md` 和 `types/runtime-sdk.d.ts`。

#### Scenario: 普通创建后打开 OpenMinis 或返回列表

- **WHEN** 用户创建一个项目但尚未预览
- **THEN** 宿主用最终文件夹的身份登记新项目。成功弹窗显示项目名称，提供「打开 OpenMinis」和「完成」两个操作。点「完成」回到项目列表，点按列表中的项目才显示启动确认。跳转 OpenMinis 失败时可以前往 App Store。

#### Scenario: 左滑从列表移除

- **WHEN** 用户在「所有项目」左滑移除一条记录并重启
- **THEN** 该记录从列表和自动恢复选择中移除，文件夹与项目数据保留。重新导入原目录恢复原项目身份。

#### Scenario: 打开损坏的项目

- **WHEN** 用户导入的项目清单格式错误、版本不受支持或缺少依赖
- **THEN** 项目显示具体问题和文件位置，用户可以修复并重试，已有文件得到保留。

#### Scenario: 重命名后切换回来

- **WHEN** 用户在「所有项目」中长按 A，打开「详情」，点「项目名称」并保存
- **THEN** 宿主同步修改 Files 中的文件夹名和清单名称，详情与列表就地更新，保留 A 的身份、数据、权限记录、Git 来源及版本历史。目标位置已存在时提示重名并保留原目录。

#### Scenario: 长按查看项目版本

- **WHEN** 用户长按一个项目并选择「详情」
- **THEN** 宿主读取该项目清单的名称和版本，关闭详情后返回原列表，启动时恢复的项目 ID 保持原值。

#### Scenario: 从公开 GitHub 仓库运行和更新

- **WHEN** 用户从「创建项目 → 从 GitHub 导入」输入公开 GitHub 仓库的 HTTPS 地址并选择「克隆并运行」
- **THEN** 宿主克隆默认分支，校验根目录的项目格式和入口，成功后登记本地副本并启动预览。
- **WHEN** 用户长按该项目并选择「拉取并运行」
- **THEN** 宿主从原分支拉取快进更新，校验工作副本后预览。文件冲突、格式错误或历史分叉时保留原工作副本和登记。

### Requirement: 协调同一目录中的外部编辑

宿主 SHALL 在有权限时协调文件读写，通过变更通知、内容版本检查和必要的前台轮询发现外部修改，并在恢复前台时重新核对版本。

#### Scenario: 云端文件稍后才可读取

- **WHEN** 独立获准访问目录的 Agent 保存了新文件，File Provider 先报告变化，稍后才提供完整内容
- **THEN** 宿主显示等待同步，待文件可读后识别完整修订并交给构建流程。

### Requirement: SwiftUI 宿主管理界面

宿主 SHALL 用 SwiftUI 提供项目列表、运行和设置界面，使用系统目录选择器授权。宿主设置的版本信息只显示已安装的 void 应用版本。默认打开上次可用项目，首次启动进入项目列表。从子应用设置点「项目管理」直接返回列表，预览失败时可从宿主的错误提示返回。

#### Scenario: 从首次启动到日常使用

- **WHEN** 用户首次启动，选择目录创建项目，点「完成」后在列表中点按该项目并确认启动，随后退出并重开宿主
- **THEN** 首次的「所有项目」列表提供创建与导入，重开后直接呈现项目。用户从子应用「设置 → 项目管理」回到列表，可选择另一个项目。正常运行时项目顶部不为管理工具预留空间。

#### Scenario: 五个自定义标签和项目内设置

- **WHEN** 用户打开带五个原生标签的项目，开发者将管理行放入「我的」页面内的设置分组
- **THEN** 首页只显示项目提供的控件和标签，状态栏沿用项目背景色。用户从设置分组直接回到宿主项目列表。旧项目尚未提供入口时，用户可在系统设置中选择启动后回到项目列表。

#### Scenario: 切换宿主语言

- **WHEN** 用户进入「设置 → 语言」，选择简体中文或 English
- **THEN** 宿主界面即时显示所选语言，重启后保留选择。项目名称和子应用自行提供的内容保留原文。

#### Scenario: 自动识别应用文稿中的子项目

- **WHEN** 用户启动宿主、进入项目列表、回到列表前台或在列表可见时将新的项目放入应用文稿
- **THEN** 列表通过直接子目录的项目配置自动显示新项目，已移除的记录继续隐藏。点按任何项目行后弹窗确认，点「启动」才加载源码及运行页面。点「取消」留在列表。
- **AND** 冷启动会先识别「我的 iPhone → void → 项目名」下的清单，再恢复上次打开的项目。

#### Scenario: 已运行的项目脚本失去响应

- **WHEN** 项目逻辑失去响应或 Web 内容进程终止
- **THEN** 用户可从「预览选项」返回项目列表，再选中原项目重新预览或打开其他项目。

#### Scenario: 等待编译或首屏时进程退出

- **WHEN** 宿主在预览新修订的过程中被系统终止，随后从桌面再次启动
- **THEN** 宿主可从原目录登记手动预览，在项目列表展示上次中断阶段，并保留已确认版本、原授权以及项目数据库。

#### Scenario: TSX 首屏启动期间连续更新

- **WHEN** 首屏 React 更新先于宿主确认，或宿主在首屏启动期间退出
- **THEN** 宿主按顺序接收首个和最新的待显示界面，在原生窗口显示后才确认可运行构建。项目列表显示中断阶段，后台按请求编号保留网页加载、原生调用、界面提交、源码复核、窗口显示和构建保存的诊断记录，供 Agent 查看。

#### Scenario: 中断后启动其他项目

- **WHEN** 项目 A 的上次预览中断，用户在列表中点按已保存的项目 B 并确认启动，随后重启宿主
- **THEN** 宿主按最近确认的选择打开 B。A 的登记、构建、数据库和中断诊断可继续查看。
