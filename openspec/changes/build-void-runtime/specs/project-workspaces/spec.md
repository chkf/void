# Spec Delta

## Purpose

用户和外部编辑器可以在 Files 中操作同一份项目源码。独立的原生宿主管理界面维护项目身份、记住用户选择的目录，并在文件服务商延迟同步或收回授权时提供恢复入口。

## ADDED Requirements

### Requirement: 选择目录并恢复访问

宿主 SHALL 允许用户选择本地、iCloud 或支持目录访问的 File Provider 文件夹，持久保存授权书签，按需取得并释放访问权。

#### Scenario: 再次启动已授权项目

- **WHEN** 上次使用的目录仍可访问，用户重新启动宿主
- **THEN** 宿主解析书签并打开原项目。脚本项目加载停用期间保存的源码，SwiftUI 项目核对源码与已安装的编译版本。

#### Scenario: 用户撤销目录授权

- **WHEN** 书签无法恢复有效访问
- **THEN** 宿主显示受影响的项目，保留其登记和数据，提供重新选择目录的入口。

#### Scenario: 原位升级后预览既有目录

- **WHEN** 用户原位更新宿主后从最近记录预览既有项目
- **THEN** 宿主在协调访问的原目录中独立读取清单及声明的入口，用逻辑相对路径收集源码，并核对原目录和项目身份。有效原目录继续使用原宿主 UUID、权限、构建与数据库。诊断区分缺失、未下载、读取失败、坏 JSON 和目录枚举遗漏。

#### Scenario: 系统文件夹选择结束

- **WHEN** 用户从列表导入或从管理页更新原目录授权
- **THEN** 请求关联固定操作和项目身份，管理页关闭后才显示系统选择器。选择或取消只处理一次，选择器关闭后主界面展示结果。等待协调时可以取消，超时调用系统协调器的取消方法。诊断按请求记录回调、授权、扫描及结束状态。应用可以在自己的 Documents 范围内直接重新扫描项目。

### Requirement: 项目格式及管理

宿主 SHALL 支持创建、导入、发现、重命名、切换和删除项目，列出最近项目和运行状态，检查配置、项目格式版本与依赖，并提供损坏恢复入口。项目以稳定身份关联数据。

#### Scenario: 创建可供 Agent 编辑的项目

- **WHEN** 用户在已选目录创建项目
- **THEN** 默认模板包含 `runtime.json`、`app/manifest.json`、`app/SwiftUI/ProjectContentView.swift`、`assets/`、`modules/`、`data/`、`logs/` 和 `README.md`。选择 React/TSX 模板时生成 `app/package.json` 和 `app/src/main.tsx`。

#### Scenario: 创建后从工作区开始

- **WHEN** 用户创建一个项目但尚未预览
- **THEN** 显示项目名称、模板、编辑入口和预览按钮。离开或重启后仍可从这里开始，首次成功预览后进入普通运行流程。

#### Scenario: 左滑移除最近记录

- **WHEN** 用户从最近项目左滑移除一条记录并重启
- **THEN** 该记录从列表和自动恢复选择中移除，文件夹与项目数据保留。重新导入原目录恢复原项目身份。

#### Scenario: 打开损坏的项目

- **WHEN** 用户导入的项目清单格式错误、版本不受支持或缺少依赖
- **THEN** 项目显示具体问题和文件位置，用户可以修复并重试，已有文件得到保留。

#### Scenario: 重命名后切换回来

- **WHEN** 用户重命名 A，打开 B，再从最近项目打开 A
- **THEN** A 使用新名称并恢复原有数据、权限记录和版本历史。

### Requirement: 协调同一目录中的外部编辑

宿主 SHALL 在有权限时协调文件读写，通过变更通知、内容版本检查和必要的前台轮询发现外部修改，并在恢复前台时重新核对版本。

#### Scenario: 云端文件稍后才可读取

- **WHEN** 独立获准访问目录的 Agent 保存了新文件，File Provider 先报告变化，稍后才提供完整内容
- **THEN** 宿主显示等待同步，待文件可读后识别完整修订并交给构建流程。

### Requirement: SwiftUI 宿主管理界面

宿主 SHALL 用 SwiftUI 提供项目运行、选择、管理、设置、SDK 版本、权限、日志、故障恢复和重启入口，使用系统目录选择器授权。默认打开上次可用项目，首次启动进入项目选择或创建界面。管理入口独立于项目页面和项目导航栈。

#### Scenario: 从首次启动到日常使用

- **WHEN** 用户首次启动，选择目录创建项目，随后退出并重开宿主
- **THEN** 首次的「项目」列表提供创建与导入，重开后直接呈现项目。运行页可通过原生「管理」入口查看权限与日志，关闭后返回原页面。

#### Scenario: 扫描本机和选中旧记录

- **WHEN** 用户在项目列表扫描本机目录或选中已有的最近记录
- **THEN** 本机发现只读取项目配置并留在列表。选中已有记录后先显示项目页，用户点「预览项目」才加载源码及运行页面。即使上次在写入最近使用指针前退出，也能从原登记恢复。

#### Scenario: 已运行的项目脚本失去响应

- **WHEN** 项目逻辑失去响应或 Web 内容进程终止
- **THEN** 用户仍然可以通过宿主界面重启、回滚或切换项目。

#### Scenario: 等待编译或首屏时进程退出

- **WHEN** 宿主在预览新修订的过程中被系统终止，随后从桌面再次启动
- **THEN** 宿主可从原目录登记手动预览，在项目列表展示上次中断阶段，并保留已确认版本、原授权以及项目数据库。

#### Scenario: TSX 首屏启动期间连续更新

- **WHEN** 首屏 React 更新先于宿主确认，或宿主在首屏启动期间退出
- **THEN** 宿主按顺序接收首个和最新的待显示界面，在原生窗口显示后才确认可运行构建。恢复页能查看对应请求的网页加载、原生调用、界面提交、源码复核、窗口显示或构建保存阶段。

#### Scenario: 中断后选择其他工作区

- **WHEN** 项目 A 的上次预览中断，用户从恢复列表选择或创建项目 B 并进入其工作区，随后重启宿主
- **THEN** 宿主按最近确认的选择打开 B。A 的登记、构建、数据库和中断诊断可继续查看。
